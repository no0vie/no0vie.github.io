## Reading the registry

- File keys F01–F26 bind paths and full-file SHA256 values. Each fragment's `sourceId` is `legacy-Fxx-suffix`; it inherits **that exact path and SHA256**, plus its own inclusive, 1-based physical line range. These are audit IDs only, not application `sourceTopicIds`. Hashes cover original bytes, including line endings and trailing whitespace; fragments are not separately normalized or hashed.
- Ranges partition each text file, including comments, demonstrations, and blank lines. Shared setup is identified where an extracted fragment depends on another range. A range is provenance, **not** a runnable extraction recipe. Demonstrations of the same objective may be separated by other objectives, as in F09.
- **E** in a contract means explicit prose, assertion, example, or comment in the source. **I** means inference from names/control flow, not an approved problem statement. Unless stated, input limits, invalid-input policy, mutation guarantees, ordering, and complexity requirements are unspecified and need editorial approval. Implementation behavior does not silently become a requirement.
- Behavior is static reasoning under the stated runtime, never a claim that output was observed by execution. Whole-file blockers take precedence; later-fragment behavior is conditional on isolation with its dependencies.
- Status **B / buggy**: a concrete implementation, answer-comment, or contract contradiction is visible statically. **I / incomplete**: missing contract, environment, implementation, or independent validation. An I fragment may be a coherent implementation; it is not a claim that its algorithm is broken. **V / verified** is reserved for an explicit tested contract; **none** qualifies in this audit. Whole-file blockers do not automatically make every isolated fragment buggy.
- Actions are proposals: **enrich** an existing objective, **new** a distinct reference/objective (no new application ID assigned), **debug** retain a labeled counterexample, **defer** restore contract/environment first, **exclude** no learning-content integration. New/debug/enrich are candidate coverage, not shipped or publication-cleared coverage.
- Reflections use **evidence** (short for “evidence from snippet”) and **hypothesis** (proposed learning value). No reflection is “verified by tests.” None infers the author's or user's current competence.
