# Study Flow modularization — decision memo, no extraction

Basis: [`architecture-audit.md`](../architecture-audit.md#verified-dependency-map-and-extraction-boundary) and Phase 2R §4. The need is **not yet established**: ask whether the goal is code reuse, separate ownership, independent release or a standalone product. A package and an independently deployed app solve different problems. No implementation is authorized.

| Option                             | Benefits / remaining coupling                                                                                                                                                     | Route, origin, risk / rollback                                                                                                                                                                                                                                             | Decision                                                               |
| ---------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| **A. Retain in portfolio**         | Same localized shell, existing static routes, progress origin, CI and SSR; shared mandatory résumé PDFs, large route→catalog import and global CSS remain.                        | Preserve old deep links and keys; simplest rollback because no move.                                                                                                                                                                                                       | **Recommend now**, pending R1–R3 fixes and real demand for extraction. |
| **B. Same-host package/workspace** | Reusable typed catalog/engine/UI + host adapters; shared host routing, SSR, PDFs, React and release remain. Similar to brnchly **build-time** integration, not a remote frontend. | Introduce lightweight route manifest and explicit reference/locale/theme/storage/CSS contracts. Keep URLs and key stable; can roll back package boundary. Only if second consumer or ownership need exists.                                                                | Defer approval pending reuse evidence.                                 |
| **C. Separate static linked app**  | Own release, metadata and shell; no résumé PDF gate for learning deploy.                                                                                                          | Static deep links and old portfolio routes need compatibility/redirect plan. Same origin at a new path shares localStorage (possible collisions); new origin cannot read old progress without consented transfer/import. Roll back by keeping legacy host routes and data. | Not now; require origin, migration, old-link and rollback plan.        |
| **D. Remote federation**           | Independent embedded runtime releases if actually needed.                                                                                                                         | Remote availability/version/cache skew, CSP/CORS where relevant, React/runtime sharing, routing/locale/CSS fallback. Host-executed remote code uses host-origin storage; iframe is different. Preserve local fallback for rollback.                                        | No demonstrated requirement; do not proceed.                           |

Existing seam evidence: `src/app/routes.ts` imports learning session IDs from catalog; lazy UI alone does not isolate content; `src/content/preparation.ts` adapts notes/exercises; `src/styles/global.css` owns study selectors; `scripts/build.ts` couples SSR/static Pages routes and both PDFs. `study-flow:v1` and old progress keys, two locales and source references must survive any future boundary. Compare deployment/test burden and rollback **before** moving files or changing URLs. Earlier audit planning bands (A 1–3 days, B 1–2 weeks, C 2–4 weeks, D 4–8+ weeks) are unapproved estimates excluding editorial backlog, not commitments. Runtime quality and extraction are separate gates.
